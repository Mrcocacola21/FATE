# FATE: недостающие VFX и промпт для создания пака

Дата проверки: 18 октября 2026. Это план изготовления и будущего подключения ассетов. Новые файлы из заказов ниже ещё не созданы и не подключены.

Охват: **37 профилей** — 28 выбираемых героев, форма Femto, отдельная приманка False Trail Token и 7 базовых классов. Проверены **154 строки hero/ability** из канонического реестра, включая открываемые варианты; у базовых Berserker/Trickster ещё 2 строки общих способностей, итого 156 строк решений. Ветки Frisk, Loki и шесть душ Asgore разобраны дополнительно. Формы EX/NEO, Undying, Centipede и Berserk относятся к владельцам, а не к новым героям драфта.

В игре уже работают общие движение, combat/hit/miss/death, подсветка выбора и постановки. NEW означает отсутствие **индивидуального тематического слоя**, а не полное отсутствие анимации/звука. Наличие PNG/WAV проверялось вместе с runtime registry и маршрутизацией. Старые README/manifest с пометкой «не подключено» не принимались за актуальное состояние.

Метки: **NEW** — изготовить новый ассет; **EXTEND** — добавить конкретную фазу к уже готовому эффекту; **KEEP** — сохранить имеющееся, не генерировать повторно; **REUSE** — использовать семейство владельца/класса; **NEEDS_EVENT** — правило есть, но сначала нужна корректная семантика нового срабатывания; **BLOCKED_RULES** — сначала реализовать само правило; **N/A** — у фигуры нет такого действия. **P1** — основной комплект; **P2** — второй проход: расширения, статусы и базовые классы. Это приоритет производства, не сложность способности.

Каждый путь в заказе относителен к `packages/web/src/assets/`. Все новые файлы лежат в подпапке `expansion/` соответствующей фигуры: имена не перезаписывают готовые ассеты. Короткий код заказа — стабильный идентификатор для переписки и проверки.

Снимок текущего запаса: **137 hero PNG**, из них 136 участвуют в runtime definitions; единственный незарегистрированный hero PNG — Undyne shift, заблокированный правилом. Во всём VFX registry 123 definitions, включая общие.

Количество — для всего P1+P2, а не рекомендация генерировать всё одним заходом. Внешние primary/accent KEEP, превью, master и manifest в эти числа не входят.

## Готовый промпт для ChatGPT / генератора VFX

Скопируй этот файл целиком в новый чат. Для отдельной партии достаточно этого промпта, технического стандарта и полного раздела выбранной фигуры.

> Ты арт-директор и художник игровых VFX для тактической настольной игры FATE. Создай согласованный, очень красочный, яркий и выразительный комплект по заказам этого документа. У каждой фигуры собственная пластика, материалы, силуэт движения и ритм: запрещён одинаковый взрыв, просто перекрашенный для всех героев. Даже малый эффект должен узнаваться по форме. Используй насыщенные акценты, чистые яркие ядра и управляемый bloom; сохрани читаемость маленьких фигур, клеток и HP.
>
> Генерируй только NEW/EXTEND выбранной партии. KEEP/REUSE/N/A/BLOCKED_RULES не генерируй. NEEDS_EVENT включай только при явном выборе этой отложенной партии. По умолчанию начни с P1 первого ещё не сделанного героя; затем выдавай по одному герою, максимум 8 PNG за ответ. Не пытайся упаковать весь документ в одну картинку. Перечисли взятые коды заказов до генерации.
>
> Для каждого заказа возьми его точный путь, профиль анимации, геометрию и индивидуальное описание из таблицы. Допиши к ним палитру и мотивы соответствующей фигуры. Выдай настоящий PNG RGBA со straight alpha и горизонтальной последовательностью одинаковых кадров 128×128 по спецификации. Не рисуй героя, фон доски, надписи, цифры, рамку приложения, нарисованную шахматную прозрачность. Не запекай камеру, глобальный поворот, целевые фигуры или обещание попадания. Для постоянной метки нужен один кадр. Создай исходные эффекты, не кадры/звуковые ассоциации из оригинальных аниме или игр.
>
> Выдай реальные скачиваемые файлы с точными именами, manifest.json с полями стандарта и превью контактного листа только для проверки. Превью не заменяет runtime PNG. Если доступный инструмент не умеет сделать анимационный strip заданных размеров, честно укажи предел и выдай покадровые исходники и точный план сборки; не называй статичную иллюстрацию готовым spritesheet. Если нет инструмента создания файлов, верни отдельные точные промпты и manifest заданий, без выдуманных ссылок. Оригинальные и готовые эффекты KEEP не перезаписывай.


## Технический стандарт VFX

Новый пакет использует единый стандарт для будущего подключения. Это требование заказа, а не утверждение о формате всех старых PNG. Старые зарегистрированные изображения сохраняются как есть.

- PNG, RGBA 8 bit/channel, sRGB, реальный straight alpha. Никакого чёрного/белого matte на полупрозрачном краю. Контроль на белом, тёмном и цветном фоне.
- Кадр 128×128; горизонтальный strip слева направо, без отступов. 12 кадров = 1536×128, 16 = 2048×128, 24 = 3072×128. Авторский темп 24 fps; длительности ниже округлены. Статика — 128×128. При желании хранить 512×512 master отдельно, не под видом runtime strip.
- Яркое ядро компактно, внешний цвет насыщен; минимум 8 px прозрачного запаса в кадре, хвост не обрезан. В размере 32–72 экранных px читаются 1–3 главных мотива. Цвет дополняет уникальный силуэт, а не заменяет его.
- Anchor по умолчанию (0.5, 0.5) в координатах эффекта. Ground-эффект центрируется на основании фигуры, позицию задаёт клиент. Directional-эффект авторски смотрит вдоль +X. Не встраивать разворот для P1/P2, наклон камеры или координатную сетку.
- Первые кадры дают быстрый читаемый импульс; последний кадр одноразового эффекта полностью прозрачен. У статичного кольца/статуса нет анимированного пульса и нет обязанности исчезать в последнем кадре. Loop=false; длительные статусы показывать только пока они существуют.
- Линия, луч, зона, снаряд и путь — разные геометрии. Рендерер использует реальные координаты, границы и сегменты из события. Не рисовать 5×5 там, где правила дают луч/зону атаки; не определять длину луча по видимым противникам.
- Для существующих сложных эффектов primary/accent остаются парой KEEP. Новый заказ по умолчанию один самостоятельный PNG. Если нужна дополнительная пара слоёв — согласовать отдельные новые имена, не самовольно удваивать список.
- Продолжительность strip — художественный исходник. При подключении вписать его в реальную фазу боя/движения; не задерживать правила ради анимации и не удваивать уже существующие cast/impact.

Visibility=public/owner/local определяет интеграция с проекцией, а не художественный файл.


## Правила подключения, которые должен учитывать пак

Новые ассеты подключим отдельной задачей. Этот документ не меняет баланс или правила. Для VFX важны следующие точки:

- Передвижение — фактически достигнутый отрезок/конечная клетка; forced move, обычный шаг, рывок и телепорт не смешивать. У River Boat уже есть транспортный пакет. Скрытое движение противника не выдавать эффектом.
- Выбор — только явное локальное действие. Deploy — подтверждённая постановка, а не наведение на клетку или отменённая заявка. Выбор в драфте и выбор на поле могут использовать одну семью, не два обязательных пака.
- Attack запускается на фазе замаха/выпуска; hit — только после разрешения результата. Miss/auto-dodge не должен выглядеть или звучать как полученный урон. Базовые шаблоны не перекрывают уникальную способность второй такой же сценой.
- Griffith → Femto и первое Undying — превращения вместо окончательной смерти. Don Quixote завершает Madness, Sans — предсмертный выбор/Last Attack. Только потом использовать окончательный death-слой там, где он уместен.
- Повторный вход в матч, восстановление истории и reconnect не запускают превращения и открытия заново. Постоянная метка может восстановиться статично. NEEDS_EVENT обозначает место, где нельзя достоверно сделать эффект по одному текущему флагу.
- Статистика HP, мультикласс и постоянные пороги сами по себе не означают отдельный каст. На ресурсы нужен спокойный UI; редкий художественный акцент на пороге — опция, не шум на каждом пункте.
- Проекции owner/public/local соблюдать и в частицах: даже край частиц способен раскрыть скрытую клетку. SFX/VFX одной сцены в будущем используют одну фазу и syncGroup, а не независимые таймеры.

**Direction Shift Undyne:** `vfx/heroes/undyne/shift.png` уже существует, но рабочей реализации способности нет. Не заказывать второй shift.png. Новый SFX этого действия отложен до реализации правила; он не входит в партии изготовления.

## Как собирать партии и принимать результат

1. Начать с P1 без NEEDS_EVENT: выбор, deploy, обычное движение/атака/смерть и недостающие основные звуки/эффекты способностей. Брать по одному герою. У героев с готовым основным attack/death/transform сохранять KEEP.
2. Затем P2: постоянные метки, защита, stealth, локальные попадания, действия новых форм и базовые классы. NEEDS_EVENT держать отдельной папкой до появления корректного события; не считать их уже работающими.
3. Для каждого заказа проверить точные имена и число PNG/кадров, технические параметры, соответствие характеру фигуры и отсутствие дублей KEEP. В manifest отмечать generated/checked, а подключение оставлять pending.
4. Проверить alpha на нескольких фонах, читаемость в размере фигуры, непрерывность кадров, края strip и отсутствие нарисованного фона. Просмотреть контактный лист и саму анимацию. Для готового пака нужен manifest фактических файлов, а не только названия.
5. Перед подключением сверить реестр заново: этот снимок относится к 18.10.2026. Одновременно проверить SFX/VFX таймлайн сцены, приватность, обе стороны доски и подавление повторов.

Шаблон следующего сообщения генератору: «Сделай VFX для [heroId], только P1 NEW/EXTEND без NEEDS_EVENT, по полному разделу и стандарту этого файла. Сохрани имена, верни файлы и manifest. После проверки перейдём к следующему герою».
