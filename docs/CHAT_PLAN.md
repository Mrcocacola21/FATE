# Чат в бою и вне боя — план

Макеты: [артефакт «Чат FATE — макеты»](https://claude.ai/artifact/V8rbAiGXGCJNcBsTk5ZFBN) — 4 экрана: чат в правой панели боя, личные сообщения на странице «Друзья», шторка на телефоне, состояния и модерация.

## Что уже есть и на что опираемся

- **Бой**: `GameRoom` в памяти, сокеты комнаты и `ConnectionMeta` (роль, место, `authIdentity`) в `packages/server/src/ws.ts`. Игрок всегда вошёл в аккаунт (`assertSeatIdentity`), зритель может быть гостем.
- **Вне боя**: у каждого вошедшего игрока на сайте открыт сокет (подписка матчмейкинга), и есть канал событий пользователя `UserChannel` (`realtime/userEvents.ts`): так приходят `notification`, `friendsChanged`, `presence`, `invite`.
- **Блокировки**: таблица `UserBlock`, `friendRepository`. Колокольчик и всплывашки — `web/src/notifications/`.
- **Админка**: страницы пользователей и матчей, `ModerationDialog`, журнал аудита.

## Предлагаемые решения (нужно подтверждение)

### 1. Каналы
- **Бой — «Бой»**: оба игрока; зрители его читают. **«Зрители»** — отдельный канал зрителей, игрокам не виден (чтобы зрители не подсказывали и не задирали игроков).
- **Комната ожидания** (до начала боя) — тот же канал «Бой», он переходит в бой без потери истории.
- **Быстрые фразы** («Удачи!», «Отличный ход!», «Упс», «Хорошая игра») — переводятся на язык получателя; работают даже при скрытом чате соперника.
- **Вне боя — личные сообщения с друзьями** (вкладка «Сообщения» на странице «Друзья», счётчик в сайдбаре). Писать можно только друзьям; заявка в друзья — единственный способ начать разговор.
- **Общий чат и чат лобби-браузера — не делаем сейчас**: им нужна полноценная модерация, а аудитория пока маленькая. Можно добавить позже на той же основе.

### 2. Хранение
- **Бой и зрители — только в памяти комнаты**, последние 100 сообщений. История приходит при входе или переподключении и пропадает вместе с комнатой. При перезапуске сервера чат боя теряется — это допустимо.
- **Личные сообщения — PostgreSQL**: таблица `DirectMessage` (отправитель, получатель, текст, время, прочитано). Хранить 180 дней, потом удалять фоновой задачей.
- В `GameState`, rules, журнал действий и снапшоты чат не попадает, ревизию не двигает.

### 3. Модерация
- **Блокировка** работает в обе стороны: ни один из двух не видит сообщений другого ни в бою, ни в зрителях, ни в личке; новые личные сообщения запрещены. Фильтрация на сервере при рассылке, не на клиенте.
- **Скрыть чат соперника на этот бой** — локально, без блокировки.
- **Лимиты**: 200 символов в бою, 1000 в личке; 5 сообщений за 10 секунд; одинаковое сообщение подряд отбрасывается; управляющие символы и лишние пробелы вырезаются; ссылки показываются текстом, не кликабельны.
- **Жалоба** из меню сообщения: сервер сохраняет копию сообщения и контекст (`ChatReport`), в админке появляется очередь жалоб.
- **Админка**: ограничить чат пользователю на срок (`User.chatMutedUntil`, запись в аудит), просмотреть жалобы и личную переписку по жалобе.
- **Фильтр брани** — не делаем на сервере. Возможна настройка в профиле «скрывать брань» на клиенте позже.
- **Настройка «Кто может писать мне»**: «Друзья» / «Никто» (по аналогии с приглашениями в лобби).

### 4. Гости, реплей, ранговые
- **Гости-зрители** читают «Бой» и «Зрители», писать не могут.
- **В реплей чат не попадает** (он не хранится).
- Ранговые и обычные бои — одинаково. В тестовой комнате чат выключен.

## Протокол (новые типы, старые не меняются)

Клиент → сервер (в сокете комнаты): `chatSend { channel: "match" | "spectators", text }`, `chatQuick { phraseId }`.
Сервер → клиент: `chatHistory { channel, messages }` при входе, `chatMessage { channel, message }`, `chatRejected { code }`.
Отправитель (`userId`, имя, место) всегда берётся из `ConnectionMeta`. Вне боя — события пользователя `directMessage` и `directMessagesRead`, отправка и история через REST (`POST/GET /api/messages/...`), чтобы работали пагинация и OpenAPI.
