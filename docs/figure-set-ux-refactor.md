# Figure Set: отчёт о рефакторинге UX

Дата: 3 октября 2026 года.

1. **Исходные проблемы.** Экран выводил семь больших вертикальных карточек слотов и повторял тот же состав справа. На каждом слоте постоянно находились Details, Change и Reset. Подробности сначала были пустыми; нажатие на кандидата немедленно заменяло героя. Поиск фильтровал списки внутри слотов, которые ещё требовалось открыть. Полноразмерный арт и способности увеличивали высоту всей страницы.

3. **Архитектура.** Компактный заголовок с поиском и меню → единственная полоса текущего состава → три колонки: классы, сетка героев, подробности. Навигация приложения остаётся в существующем AppShell. Состояния `activeClass`, `inspectedId` и `search` управляют просмотром; сохранённый `FigureSetState` остаётся единственным источником выбранного состава.

4. **Навигация классов.** Используется существующий порядок `BASE_CLASSES`, без нового списка классов. Число героев вычисляется из `HERO_CATALOG`: по пять доступных позиций на каждый класс, включая базовую. Класс сразу открывает свой список и текущего выбранного героя. На первом открытии просматривается сохранённый герой Assassin. Нажатие класса завершает поиск; очистка поискового поля возвращает последний активный класс.

5. **Браузер героев.** Карточка показывает портрет, имя и отметку Selected; рамка и `aria-pressed` показывают просматриваемого героя. Кнопки Details и Change удалены. Карточки доступны через Tab, Enter и Space. Пустой список безопасно показывает локализованное сообщение.

6. **Поиск.** Проверяет все классы, оригинальное и локализованное имя, ID и локализованное название класса. Результаты показывают класс героя. Можно открыть Papyrus из Assassin и выбрать его непосредственно для Spearman. Выбор сохраняет запрос и активный класс; очистка поля возвращает список активного класса.

7. **Подробности и способности.** Общий компонент показывает имя, класс, арт, описание при наличии, HP, урон, тип перемещения, дальность атаки, существующие визуальные формы и способности. Используются реальные `HeroMeta` из `/api/heroes` и прежний `FigureSetAbilityCard`, включая представление сложных ресурсов. Поля cooldown/rarity/targeting и новые статистики не добавлены. Для базового описания используется перевод. Сохранена пометка Giant у Lechy. При смене героя прокрутка подробностей возвращается наверх. Загрузка, ошибка и Retry размещены внутри подробностей; каталог остаётся доступным.

8. **Полоса состава.** Ровно семь небольших кнопок с токеном, названием класса и именем выбранного героя. Длинное имя сокращается визуально; полное доступно через tooltip и имя кнопки для средств доступности. Нажатие открывает класс и выбранного героя. После сохранения появляется короткое сообщение. Дублирующего списка состава больше нет.

9. **Семантика выбора.** Нажатие карточки только просматривает героя. Явная кнопка Select for соответствующий класс обновляет только этот слот, timestamp и прежнее локальное сохранение. Уже выбранный герой показывает отключённую кнопку Selected. Просмотр и поиск сохраняются, перехода страницы нет.

10. **Сбросы.** Reset to Base находится в действиях подробностей и доступен, если соответствующий слот отличается от базового. Он сбрасывает только этот класс и открывает базового героя. Reset All использует прежний `resetToBaseState`, но подтверждение теперь отображается существующим компонентом Dialog. Cancel ничего не меняет.

11. **Импорт, экспорт и меню.** Действия перенесены в компактное раскрываемое меню `⋯`; общий сброс отделён разделителем. Меню доступно с клавиатуры и закрывается по Escape или нажатию снаружи. Импорт использует прежний FileReader и валидатор, показывает локализованные ошибки и сообщение об успехе; допустимый просматриваемый герой сохраняется. Экспорт по-прежнему скачивает `figure-set.json` с прежним JSON. Поддерживаются как объект состояния версии 1, так и прежний импорт объекта selection.

12. **Прокрутка desktop.** Страница занимает `100dvh` за вычетом отступов AppShell. Заголовок и состав находятся вне прокрутки; классам отдельная вертикальная прокрутка не нужна. Две области overflow находятся в списке героев и содержимом подробностей. Имя и основной выбор остаются видимыми. Для высоты меньше 600px предусмотрена рабочая область 360px и допустимая прокрутка страницы, чтобы элементы не сжимались до непригодного размера.

13. **Планшет и телефон.** До 1100px используются две колонки и диалог подробностей с существующим управлением фокусом. До 600px классы становятся горизонтальной полосой, герои — сеткой из двух колонок. Полоса состава прокручивается горизонтально; на планшете используется раскладка 4 + 3. Диалог поддерживает Tab, Escape и возврат фокуса на открывшую карточку. Смена ширины окна не открывает диалог автоматически.

14. **Сохранённая функциональность.** Источник допустимых героев — существующий `HERO_CATALOG`; подробности — существующий `/api/heroes`. Не менялись ключ `FATE_FIGURE_SET_SELECTION_V1`, версия и формат сохранения, базовые ID, классы, допустимость героев, связь состава с матчем или маршрут `/figures`. Обновление страницы сохраняет состав. SPA-конфигурация не менялась; удалённое развёртывание не выполнялось.

15. **Тесты.** Девять новых тестов проверяют порядок классов, семь слотов, начальный сохранённый герой, все классы, отсутствие сохранения при просмотре, явный выбор, поиск между классами, неизменность других слотов, оба сброса и отмену, способности всех 35 доступных героев из реального registry, загрузку/ошибку/повтор и совместимость импорта/экспорта. Браузерный сценарий дополнительно проверяет скачанный JSON, загрузку файла, сохранение после reload, клавиатуру, мобильный фокус, переполнение страницы и украинскую локализацию.

16. **Визуальная проверка.** Просмотрены скриншоты 1920×1080, 1366×768, 768×1024 и 390×844; также проверены длинные способности Mettaton, результаты поиска, меню, планшетный/мобильный диалог и украинский экран. Desktop не имеет вертикального переполнения страницы; горизонтального переполнения нет на всех четырёх размерах. Браузерные проверки используют изолированный профиль и реальные данные registry через подменённый ответ API; пользовательское хранилище и рабочая БД не затрагиваются. Артефакты: `packages/web/test-results/figure-set/`, включая `results.json` и PNG.

17. **Выполненные команды.** `npm run -w web typecheck`, `npm run lint`, `npm run build`, `npm run test`, `npm run -w web test:figures`, `npm run -w web test:figures:e2e`, `npm run -w web test:i18n`, `npm run -w web test:draft`, `npx prettier --write` для изменённых компонентов, CSS и тестовых файлов, `git diff --check`. После обнаруженных ошибок исправлялись проверки/интерфейс и запускались соответствующие команды повторно.

18. **Итоговые результаты.** Typecheck: exit 0. ESLint: exit 0, **0 ошибок, 0 предупреждений**. Build: exit 0. Общий `npm run test`: exit 0; rules, boundaries, server и все включённые frontend suites проходят. Frontend suites этого общего запуска: auth 31/31, profile 11/11, matches 15/15, shell 9/9, figures 9/9; ошибок и пропусков нет. Отдельно: i18n 5/5, draft 10/10. Браузер: все 12 групп проверок прошли, `pageErrors: []`. Сборка выводит сообщения инструментария о CJS API Vite, возрасте Browserslist и размере bundle; зависимости и настройки сборщика не менялись. Логи итоговых команд находятся в `.tmp/figure-set-*.log`.

19. **Намеренно оставлено прежним.** Rules engine, способности, баланс, базовые герои, сериализация игрового состава, backend/API, DB, auth, WebSocket и создание комнат. Новый backend управления героями, новые зависимости, новые изображения и второй маршрут Figure Set не добавлялись.
